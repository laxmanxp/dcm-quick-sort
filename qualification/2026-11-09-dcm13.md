## Harness defect found and corrected locally

The first native attempt stopped safely at `RegOverridePredefKey` with error 6, before any installer action. Its receipt records unchanged live DCM registry trees and removal of the temporary private registry key.

The Windows SDK declares HKCU through a signed LONG-to-pointer conversion. The harness was supplying the zero-extended 32-bit value on amd64. The locally prepared correction adds `qualOverrideHKCU = ^uintptr(0x7ffffffe)` and uses it only for override and reset. Ownership-marker checks still use the installer's original handle value, so the test cannot proceed unless the real installer access path is redirected. Private-path checks, exact-byte assertions, cleanup checks, and live-registry comparisons remain intact.

Original harness blob `c235b6096025f73b8f8bdb26d3690581e2b6791d` was reconstructed and hash-verified locally. Final blob `4dd2e4fe6e310925c4ce5e37349c976a64b33524` matches the local file. An unintended declaration/assignment transport difference was detected and corrected before native execution. The application and installer implementation files were not modified. Local parsing and an isolated 64-bit numeric ABI test passed; attempted cross-compilation hit the local command deadline and is not claimed as a PASS. Native compilation and the subsequent engine run provide the relevant Windows evidence.

Primary references: Microsoft Windows SDK `winreg.h` in `microsoft/win32metadata` (blob `e48c86d731096149cbc60016057cb0531af3ca56`, HKCU definition); Microsoft Learn, RegOverridePredefKey. The latter documents process-local mapping and reset with a null replacement handle.
