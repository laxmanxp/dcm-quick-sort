## Failures diagnosed and corrected

Two original failures were date-order fixtures: `TestInboxAgeFilters` and `TestInboxSortModes`. Their helper changed modification time but left Windows creation time at the actual execution time. The app sorts Date Created using creation time, while Age filtering uses modification time. The native diagnostic showed creation on 10 November but the requested/modification time on 22 September. The Windows-only helper now sets and independently reads back creation time; the original ordering expectations remain unchanged. The non-Windows fixture keeps the existing modification-time fallback.

Five original failures were multiline source checks: Clear Filters wiring, automatic Rename-tool application, PDF double-scaling prevention, deferred Processed refresh during batches, and Fit Width top anchoring. The Windows checkout contained 5,960 CRLF lines, while the assertions expected LF. The test reader now normalizes only CRLF to LF, including the secondary PDF source reads. Source tokens, indentation and every original assertion remain intact. This corrects source-check portability; it does not demonstrate visible UI behavior.

A new Windows fixture-contract test first reproduced both problems natively. After the correction, both cases passed, with requested, actual creation and modification timestamps all equal. Application and installer implementation files were not changed.

Changes were prepared locally, checked with gofmt, stored in GitHub, and validated through the registered FlowDev update/test sequence on Lenovo. Relevant original files were reconstructed from the supplied v1.0.70 archive plus the existing batch-journal test changes and verified against their current Git blob hashes before editing. No source was edited on Lenovo.
