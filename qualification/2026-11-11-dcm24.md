The helper is designed to send real Windows input-stream Ctrl/Shift mouse events through SendInput, not set selection directly with LB_SETSEL. It checks the owned foreground process, row geometry, an independent row hit-test, physical screen coordinates, unobscured control and idle modifier/button states. Input delivery and key/button releases are checked. This design has not yet been validated on Windows; it is not manual user acceptance.

The planned workflow covers single selection, nonadjacent Ctrl selection, Ctrl removal down to one and zero selected files, forward/reverse Shift ranges, plain-click collapse, explicit Next after multi-selection, a filtered range, cancellation and a representative confirmed two-file move. File names and hashes are checked independently, including the four unselected files. Only six disposable TXT/CSV files and isolated settings are used. A passing representative move would not close the later full Batch Move/Undo steps.

## Source-review hypothesis, not a confirmed defect

The current selection-change handler takes the ListBox caret index, while single-file Move uses currentFile. Ctrl-deselecting one of two selected rows may leave the caret on an unselected row. The new test deliberately checks this boundary and the zero-selection boundary. This is a source-inspection hypothesis only: do not label it a reproduced product defect or apply a speculative fix before obtaining native evidence.
