## Standalone DCM QuickSort

DCM QuickSort remains a separate Windows desktop application for previewing files, renaming them, moving them into the Vault, and recovering or undoing operations. FileFlowSuite, Flow Search, DeepSearch and FileFlow remain separate applications/windows.

This candidate builds on the recovered DCM application and its existing Go functions and Windows PDF preview path. Finalizing it does not require a Walk UI migration, a replacement PDF engine, or a new printing feature. PDF and other preview acceptance still require the native checks below.

## Candidate fixes

### Batch history and configuration preservation — native passes recorded

- **Durable batch membership (D3):** conflict operations carry their batch identifier into the move journal, so completed operations remain associated with their batch after worker completion and restart.
- **Complete configuration import and restore (D4):** naming templates now use the same supported-file and checksum contract as configuration export and backup. Valid exports containing templates can be imported or restored; modified backup content remains rejected.
- **Installer preference preservation (D5):** the installer accepts the app's PDF default-view and Vault-root settings and retains them when updating the source folder. Legacy settings and rejection of unsupported keys or invalid value types remain covered.

These claims have native test evidence at commit `7c413fd530126398732cab7cda426b591514deb5`: D3/D4 passed within the app regression run, and the full installer unit suite passed **24 tests, with no failures or skips**. This is unit/regression evidence at that commit. It does not certify the final candidate package or a complete installer lifecycle.

### File safety — implementation awaiting native GREEN

- **Same-file conflict protection (D1):** refuse destructive conflict actions when source and destination resolve to the same physical file, including hard-link and case aliases.
- **Verified source retirement (D2):** check the original source identity and bytes against the completed destination while holding Windows file guards; retain remaining files when verification or retirement is unsafe.
- **Duplicate Undo proof (D6):** persist the original size and SHA-256 before duplicate removal, require that evidence before restoring a source, and handle changed or unproven surviving copies conservatively during restart recovery.

The earlier defects were reproduced natively before these fixes. A successful native result for the fixed D1/D2/D6 candidate has **not yet been recorded**.
