## Minimal change and behavior

Only three lines were added to `isRenameOnlyRecord` in `app-src/core.go`. The function now accepts only ordinary `move` records and legacy records with an empty Kind for its existing same-folder rename check. Duplicate-removal, replacement and unknown operation kinds cannot enter ordinary rename-chain reconciliation.

For the reproduced sequence — remove an exact duplicate, move its surviving copy, then restart — recovery now marks the duplicate-removal record for attention and preserves the later valid move history. The regression verifies that the removed endpoints stay absent and the surviving file retains the original bytes. This is conservative handling, not a claim that automatic duplicate restoration follows files to arbitrary new paths.

The previous DCM-06 no-overwrite test also remains GREEN. No tests or assertions were changed. No UI, preview, printing, installer or framework code was modified.
