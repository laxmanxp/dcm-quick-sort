## External Open scope and safety

The test physically clicked the exact enabled ordinary **Open** item of the owned popup after verifying menu identity, item readback, target geometry and input safety. The prior selection was `03-wrong-open.cmd`; the right-click target was `04-external open.cmd`. Both are harmless locally generated fixtures that only write distinct markers inside the disposable lab and exit. Only the target marker appeared, with the expected unique token. No file association was changed and no user document was opened.

This proves the actual native Open path through the default Windows command-file handler. It does **not** certify every document association, the separate Open toolbar button, bulk context-menu actions, keyboard invocation or every Shell extension/command. The new menu intentionally targets a single clicked file. Shell Cut/Delete and similar commands are external to DCM's operation journal/Undo; DCM's own Rename/Move controls retain their separate tracked workflow. A Windows-provided Print entry is not a new DCM printing pipeline.
